# Протокол тестирования базы данных FoodExpress

## 1. Окружение

| Параметр | Значение |
|---|---|
| СУБД | PostgreSQL 18.6 |
| Схема | `konev_food` |
| Тестовая база | `foodexpress_restore_check` |
| Роль-аудитор | `inspector` |
| Дата проверки | 14.11.2026 |

Проверки проводились на отдельной тестовой базе данных `foodexpress_restore_check`. Основные базы `foodexpress_dev` и `foodexpress_test` не изменялись в ходе заключительных проверок восстановления и работы триггеров.

Восстановление структуры базы данных, настройка прав и первоначальное заполнение тестовыми данными выполнялись под пользователем `postgres`. Проверки доступности функций, процедур и представлений, для которых проверялись права аудитора, выполнялись под пользователем `inspector`.

Проверки, изменяющие данные, проводились внутри транзакций с последующим `ROLLBACK`, чтобы не сохранять тестовые изменения.

## 6. Проверка ограничений и триггеров целостности данных

Проверены следующие механизмы контроля целостности.

### 6.1. Проверка соответствия товара ресторану заказа

Выполнена попытка добавить в заказ товар, принадлежащий другому ресторану.

Операция была отклонена триггером `check_order_product_restaurant()` с сообщением:

```text
Товар не принадлежит ресторану, оформившему заказ
```

**Результат:** добавление товара другого ресторана в заказ запрещено.

### 6.2. Проверка изменения ресторана в заказе

Выполнена попытка изменить ресторан у заказа, в котором уже находился товар другого ресторана.

Операция была отклонена триггером `check_order_restaurant_change()` с сообщением:

```text
Нельзя изменить ресторан: в заказе есть товары другого ресторана
```

**Результат:** изменение ресторана заказа, нарушающее целостность его состава, запрещено.

### 6.3. Проверка суммы платежа

Выполнена попытка изменить сумму существующего платежа так, чтобы она перестала совпадать с суммой заказа.

Операция была отклонена триггером `check_payment_amount()` с сообщением:

```text
Сумма платежа должна совпадать с суммой заказа
```

**Результат:** триггер предотвращает сохранение платежа с некорректной суммой.

### 6.4. Проверка объекта отзыва

Выполнена попытка оставить отзыв о товаре, которого нет в составе указанного заказа.

Операция была отклонена триггером `check_review_target()` с сообщением:

```text
Товар отсутствует в заказе
```

**Результат:** проверка запрещает оставлять отзыв о товаре, не входящем в соответствующий заказ.

### 6.5. Проверка изменения итоговой суммы заказа

Выполнена попытка изменить `total_amount` заказа, для которого уже существует платеж с другой суммой.

Операция была отклонена триггером `check_order_total_change()` с сообщением:

```text
Нельзя изменить сумму заказа: она не совпадает с существующими платежами
```

**Результат:** изменение итоговой суммы заказа, нарушающее соответствие существующим платежам, запрещено.

Все перечисленные проверки выполнялись внутри транзакций с последующим `ROLLBACK`.

### 6.6. Проверка изменения ресторана у товара

Проверены два сценария изменения `restaurant_id` у товара:

1. Для товара, который уже используется в заказе, выполнена попытка изменить ресторан. Операция была отклонена триггером `check_product_restaurant_change()` с сообщением:

```text
Нельзя изменить ресторан товара: товар уже используется в заказах
```

2. Для товара, который не используется ни в одном заказе, изменение ресторана прошло успешно.

Оба теста выполнялись внутри транзакций с последующим `ROLLBACK`.

**Результат:** триггер запрещает менять ресторан у товара, включённого в существующие заказы, но допускает изменение для товара, который ещё не используется в заказах.

## 7. Синхронизация статуса оплаты заказа

Проверена работа функции `refresh_order_pay_status()` и триггера `update_order_pay_status()`.

В рамках одной транзакции последовательно проверены три операции:

| Операция с платежом | Ожидаемый статус оплаты заказа | Фактический результат |
|---|---|---|
| Изменение статуса платежа с `success` на `error` | `error` | `error` |
| Изменение статуса платежа с `error` на `success` | `paid` | `paid` |
| Удаление платежа | `pending` | `pending` |

После проверки выполнен `ROLLBACK`. Контрольный запрос подтвердил восстановление исходного платежа и статуса заказа `paid`.

**Результат:** статус оплаты заказа автоматически обновляется при изменении и удалении платежа.
